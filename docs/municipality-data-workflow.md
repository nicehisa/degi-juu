# 自治体データの調査・追加・保守

## 保存場所と型

| 用途 | 場所 | 備考 |
| --- | --- | --- |
| 型・固定掲載データ | `src/data/municipalities.ts` | `Municipality` / `MunicipalityType` / `MunicipalityStatus` |
| 追加掲載データ | `src/data/autoMunicipalities.json` | `Municipality[]`。サイトでは固定分と統合する |
| 地方・都道府県 | `src/data/regions.ts` | 九州を含む表記は `九州・沖縄` |
| 特典カテゴリ | `src/data/benefitCategories.ts` | `tourism`, `stay`, `food`, `event`, `community`, `info`, `nft`, `experience`, `coupon`, `other` |
| 許諾確認済みストックと表示画像の選択 | `src/lib/municipalityImages.ts` | CLIもこの定義を参照する |
| 新しいRSS調査の候補記事 | `data/candidates.json` | 非公開。未確認の記事であり、掲載用データではない |
| 検索の実行結果 | `data/discovery-report.json` | 検索条件・件数・失敗を記録 |
| 新しい死活・終了表現チェック | `data/municipality-checks.json` | 前回との比較基準も保存 |
| ひな形・確認メモ | `data/drafts/*.json`, `data/research-notes/*.json` | サイトには取り込まない |

`data/` は `public/` ではなく、アプリからもimportしていません。ただしGitHubリポジトリやActionsの閲覧権限がある人には見えます。秘密情報・個人情報・未公開の自治体連絡先は入れないでください。

既存のGemini検索・自動掲載（`src/data/detectedMunicipalities.json` と `publish:programs`）と、サイト表示用の `public/data/program-checks.json` の仕組みは維持しています。既存の自動掲載ワークフローにも、コミット前の `data:validate` を追加しました。RSS候補を既存の自動掲載へ無条件に渡すことはありません。

## 1. 候補記事を集める

```bash
npm run data:discover
npm run data:discover -- --days=365 --query='"デジタル住民票"'
```

標準は7キーワード・直近90日。APIキー不要のGoogle News RSSを順番に取得します。標準の検索語を引用符で囲み、取得後も住民・会員制度の語句で絞って、市民教育・一般的なDX・スポーツ速報などの混入を抑制します。「ふるさと住民登録」だけの記事は具体的な市区町村名らしい表記も必要とし、一般的なセミナーや制度動向を抑制します。これは厳密な自治体名の確定ではないため、候補の目視確認は必要です。`--query` は複数回指定でき、Google検索構文をそのまま使えます。

掲載済みの自治体名・URLを、受付終了分も含めて除外します。記事URLは追跡用パラメータを除いて重複排除し、再実行時も手動の審査状態・メモを保ちます。新たに掲載された自治体は候補一覧から外します。検索失敗時も既存候補を失わず、失敗を記録して終了コード1を返します。

Google Newsの記事URLは仲介URLの場合があります。公式URLとはみなさず `articleUrl` として保存し、自治体名と `officialUrl` は原則 `null` のままにします。記事タイトルだけで自治体・制度の同一性を確定できない例は残るため、候補件数は「新しい自治体数」ではありません。同名自治体、複数自治体を扱う記事、国の制度動向、転載記事は目視確認してください。記事本文の無断転載や画像取得は行いません。

## 2. 公式URLと終了表現を確認する

```bash
npm run data:check
npm run data:check -- --strict
npm run data:check -- --alert-on-change
```

全掲載データの `officialUrl` を順番にGETし、最終HTTPステータス・リダイレクト先・HTMLタイトル・本文を調査します。タイムアウトは接続先ごと15秒、間隔は500ms。`--timeout-ms` / `--interval-ms` で調整できます。HTTPSのみ許可し、リダイレクトごとにURLとDNSを検査し、検査した公開IPに接続を固定します。内部IP・ローカルホスト・認証情報入りURL・過大な応答は取得しません。

「受付終了」「販売終了」「募集を終了」「終了しました」などの周辺文を保存します。ナビゲーションやスクリプト、並び替えの「販売終了が近い／遅い」、明確な否定表現は除外します。初回は基準値を作り、「新たに出た」とは判定しません。2回目以降に、同じ公式URLの直前の正常取得と比較します。URL変更時は基準をリセットし、取得失敗時は前回の正常な基準を維持します。

- HTTPが200以外、HTTP200のエラー画面、取得失敗は警告・アラート。
- 受付終了以外の掲載制度で終了表現を見つけた場合は警告。初回または新規表現の出現時はアラート。
- すでに終了と登録された制度の終了表現は記録のみ。
- PDFはHTTP到達のみ確認し、本文未解析の警告。OCR・PDF本文解析は行わない。
- 別年度の募集や旧会員制度の終了でもヒットするため、制度全体の終了とは断定しない。

通常は処理完了で終了コード0、スクリプト自体の失敗は1。`--strict` は警告が1件でもあれば2、`--alert-on-change` は取得異常・新たな終了表現などのアラートがあれば2です。既知のPDF・同じ終了表現の警告はレポートに残しつつ、後者では毎日失敗通知を繰り返しません。

**この処理は公開データの `status` / `lastChecked` / 費用を変更しません。** 取得日と制度内容の情報確認日は別物です。担当者が本文を確認し、募集状況・費用・特典を更新したときだけ `lastChecked` を更新してください。

## 3. ひな形を生成する

```bash
npm run data:scaffold -- --name="山古志" --url="https://自治体または発行元の実際の個別ページURL"
npm run data:scaffold -- --name="長岡市" --prefecture="新潟県" --slug="nagaoka-niigata" --url="https://自治体または発行元の実際の個別ページURL"
```

URLは実在するHTML個別ページに置き換えてください。`--dry-run` を付けると表示だけでファイルを作成しません。正式な自治体名と地区名は別です。「山古志」の入力だけで「長岡市」と推測して書き換えません。

HTTP200の有効なHTMLからタイトル・概要を取得し、`Municipality` 型に準拠したJSONを `data/drafts/<slug>.json` に生成します。`slug` 未指定時は自治体名・都道府県由来の安定したハッシュを使います。明示したslugの形式・重複を確認し、既存ファイルは上書きしません。

都道府県は引数または本文中の一意な表記から決め、地方は `regions.ts` から取得します。不明・複数候補の場合は `要確認` とし、公開前に確定してください。制度タイプはタイトルからの仮分類で、必ず確認してください。料金・募集状況・対象者は `要確認`、特典は未確定なら空配列。0円や特典を勝手に補いません。

情報確認日は成功したHTML取得日の日本時間日付で、notesにも「ひな形取得日」と記録します。募集内容の目視確認済みという意味ではありません。失敗・404・エラー画面ではひな形を作りません。

画像は既存の許諾確認済みストックから使用数の少ないものを割り当て、出典・クレジット・altも入れます。実際の自治体の写真とは扱いません。有限の素材のため完全な画像一意性は保証しません。レビュー項目とライセンス情報は `data/research-notes/<slug>.json` に保存します。

## 4. 検査して追加する

```bash
npm run data:validate
npm run data:validate -- --draft data/drafts/nagaoka-niigata.json
npm run test:updates
npm run build
```

検査内容:

- 既存のTypeScript型をそのまま使った `satisfies Municipality[]` の型検査（仮想ファイル上で実行）。
- 必須項目・空文字・数値・HTTPS URL・日付形式・未来日。
- 固定データと追加JSONの元データ全件のid・slug・自治体重複。サイト側の重複除外で隠れる不備も検出。
- 都道府県と地方の対応、特典IDのタイポ・重複。
- 実際に表示される画像の存在、alt・出典・クレジット、使用画像の重複。

エラーがあれば終了コード1。通常のストック共用は警告で、注目の制度内の重複や複数自治体の許諾済み実写共用はエラーです。`--strict` で警告も失敗にできます。ドラフトの不明な都道府県は警告ですが、そのまま公開JSONに入れるとエラーになります。

公式情報・料金・受付状況・特典・自治体名・画像権利を目視確認して、ひな形の `notes` と `lastChecked` を更新してから、レコードを `src/data/autoMunicipalities.json` の配列に追加します。既掲載の更新なら元の固定／追加レコードを編集し、同じ自治体を二重に追加しないでください。ドラフトとレビュー用メモのままでは本番には載りません。

追加後に `data:validate`、テスト、ビルドを再実行し、差分確認後にコミット・pushします。RSS候補を未審査のまま公開する操作はありません。

## GitHub Actions

`Research and validate municipality data` を追加しました。

- PR: データ・スクリプト等の変更時に型・整合性と回帰テストを実行。外部ページは取得しない。
- 毎日7:47頃（日本時間）およびRun workflow: RSS収集→順次URL確認→レポートをArtifact保存→候補と比較基準をmainに保存。
- 自動実行に検索APIキーは不要。GitHub Actionsの実行・mainへのbot pushが許可されていることが必要。
- 取得失敗・新しい終了表現はジョブ失敗として可視化。通知はGitHubのActions通知設定に従う。
- 公開レコードは変更しない。既存日次ジョブと同じ書き込み排他グループを使う。

GitHub側の混雑で時刻は遅れる場合があります。ブランチ保護で直接pushできない場合はArtifactからレポートを取得してPR経由で保存してください。基準ファイルを保存しないと、次回も初回調査になります。
