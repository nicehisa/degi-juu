# デジじゅう 事業計画書 Ver.1

作成日: 2026-08-31

## 1. 事業の目的

デジじゅうは、全国のデジタル住民票、デジタル住民NFT、デジタル住民証、地域ファン向け会員証を比較できる情報サイトから出発し、将来的には自治体・観光協会・DMO・地域商社向けに、制度設計、NFT/アプリ制作、販売、CRM、広告PRを一気通貫で提供する地域ファン制度プラットフォームへ拡張する。

目指す姿は、以下の3段階である。

| 段階 | 位置づけ | 主な提供価値 |
| --- | --- | --- |
| Phase 1 | 比較・送客メディア | 制度を探すユーザーと自治体公式ページをつなぐ |
| Phase 2 | 自治体向け制作・運用支援 | デジタル住民証、NFT、会員証、LP、フォーム、CRMを制作・運用する |
| Phase 3 | 販売モール・SaaS | 制度の販売、購入者管理、特典管理、メール/LINE配信を提供する |

## 2. 現状課題

自治体側には、関係人口づくりや地域ファン化のニーズがある一方で、デジタル住民票やNFT型会員証を自前で企画・制作・販売・運用するには負担が大きい。

ユーザー側には、各自治体の制度情報が分散しており、地域、特典、制度タイプ、販売状況から横断的に比較しづらい課題がある。

デジじゅう側の現状は、比較サイトとしての土台はできているが、収益化を本格化するには以下が不足している。

| 不足項目 | 現状 | 必要な状態 |
| --- | --- | --- |
| 自治体向け商品設計 | 掲載依頼フォームはある | 制作・運用・販売代行メニューを明確化 |
| 決済機能 | 未実装 | Stripe等による販売・手数料徴収 |
| 購入者管理 | 未実装 | 購入者、保有証明、特典利用履歴を管理 |
| NFT発行 | 未実装 | 外部NFT基盤連携または独自発行方針を決定 |
| 法務確認 | 注意書き中心 | 契約書、利用規約、販売規約、景表法チェック |
| 営業資料 | 未整備 | 自治体向け提案書、価格表、導入事例の整備 |

## 3. 原因仮説

この市場で導入が広がりにくい主因は、自治体が「何を作ればよいか」よりも、「どう安全に運用するか」で止まりやすい点にある。

| 課題 | 原因仮説 |
| --- | --- |
| 自治体の導入判断が進みにくい | NFT、住民票、ふるさと納税との誤認リスクがあり、庁内説明が難しい |
| 既存制度が単発企画で終わりやすい | 販売後のCRM、特典運用、継続接点が不足している |
| ユーザーが探しづらい | 制度情報が自治体サイト、NFT販売ページ、観光協会サイトに分散している |
| 収益化しづらい | 比較メディア単体では広告単価が限定的 |

## 4. 改善方針

デジじゅうは、単なるNFT販売サイトではなく、「地域ファン制度の設計・販売・運用基盤」として展開する。

差別化の軸は以下の3つとする。

| 差別化軸 | 内容 |
| --- | --- |
| 法務リスクに配慮した表現設計 | 法律上の住民票、住民登録、ふるさと納税、税控除、投資性と誤認されない導線を標準化 |
| 自治体向けの運用パッケージ | LP、申込、決済、特典管理、問い合わせ、メール/LINE配信までまとめて提供 |
| 比較メディアとの連動 | 制作した制度をデジじゅう内で掲載・送客し、初期集客を支援 |

## 7. 技術構成案

| 領域 | 推奨構成 |
| --- | --- |
| フロントエンド | Next.js / TypeScript / Tailwind CSS |
| データベース | Supabase Postgres |
| 管理画面 | Next.js App Router + Supabase Auth または Clerk |
| 決済 | Stripe Checkout / Stripe Connect |
| メール | Resend |
| LINE | LINE Official Account / Messaging API |
| NFT | 初期はHEXA等の外部基盤連携、本格化後に独自発行を検討 |
| 画像/ファイル | Supabase Storage または Vercel Blob |
| 分析 | Google Analytics / Search Console / 管理画面KPI |

初期はNFTを独自発行しない方針が安全である。まずは外部NFT基盤の販売ページへ連携し、デジじゅう側は比較、送客、PR、購入前説明、自治体向けLP制作で収益化する。その後、通常のデジタル会員証販売からモール機能を開始し、法務確認後にNFT機能を段階的に拡張する。

## 8. 法務・リスク対策

| リスク | 対策 |
| --- | --- |
| 法律上の住民票と誤認 | 「法律上の住民票・住民登録・転入手続きではありません」を全ページに明記 |
| ふるさと納税と誤認 | 「ふるさと納税ではなく、税控除の対象ではありません」を明記 |
| NFTの投資性 | 値上がり、儲かる、資産性、一番おすすめ等の表現を禁止 |
| 自治体公式サイト誤認 | 「デジじゅうは自治体公式サイトではありません」をヘッダー/フッターに明記 |
| 景表法 | 特典表現は条件、期間、変更可能性を併記 |
| 決済/返金 | 販売規約、特定商取引法表示、返金ポリシーを整備 |
| 個人情報 | プライバシーポリシー、データ保持期間、外部委託先を明記 |

公開前に弁護士確認が必要な文書は以下。

| 文書 | 必要度 |
| --- | --- |
| 利用規約 | 高 |
| 販売規約 | 高 |
| 特定商取引法に基づく表記 | 高 |
| プライバシーポリシー | 高 |
| 自治体向け業務委託契約書 | 高 |
| 広告掲載規約 | 中 |
| NFT販売時の注意事項 | 高 |

## 12. 営業戦略

初期ターゲットは、自治体本体だけでなく、観光協会、DMO、地域商社、道の駅、商工会を含める。

| ターゲット | 提案内容 |

| 自治体企画課 | 関係人口創出、地域ファン制度、移住前接点づくり |
| 観光協会/DMO | 観光リピーター、イベント参加者、地域アンバサダー化 |
| 地域商社 | 特産品販売、会員証、限定販売、CRM |
| 道の駅/観光施設 | デジタル会員証、クーポン、来店促進 |

営業導線は以下の順で作る。

1. デジじゅう内に自治体向けLPを追加
2. ホワイトペーパー「デジタル住民制度の始め方」を作成
3. 資料請求フォームからリード獲得
4. 月1回のオンライン説明会を開催
5. 初期導入3自治体を事例化
6. 導入事例を記事・広告・自治体向けDMで展開

## 15. 提案まとめ

デジじゅうは、比較サイト単体では広告収益に限界があるが、自治体向けの制作・運用・販売支援に拡張することで、初期制作費、月額運用費、販売手数料、広告PRを組み合わせた収益性の高い事業にできる。

最初からNFTモールを大きく作るのではなく、まずは自治体向けLP、資料請求、管理画面、Supabase化、広告PR管理を整え、受注実績を作る。その後、通常のデジタル会員証販売からモール機能を開始し、法務確認を経てNFT連携へ進むのが現実的である。

初年度の目標は、導入自治体10件、売上2,500万円、継続月額売上150万円を目安とする。3年目には導入自治体60件、年間売上1.8億円を標準ケースの目標とする。
